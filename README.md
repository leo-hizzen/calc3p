# Calc3P

**立直三麻（三人麻将）计算型 AI —— 给 [Akagi](https://github.com/shinkuan/Akagi) 用的 mjai bot**

作者：**愚**

不训练、不推理神经网络，每一手都靠显式计算得出：向听数与进张、和牌率、番符点数、铳率，最后合成一个期望值。

```
EV = P(和牌) × 打点 − 铳率 × 放铳损失
```

单步决策耗时 **p99 14 ms**（预算 3000 ms），纯 Python，除 `mahjong` 库外无依赖。

## 为什么用计算而不是神经网络

公开可用的三麻 Mortal 权重只有一份（Akagi 官方随附的 `mortal3p`，120 万参数，作者自述「仅用于验证安装，不建议实战」）。四麻的大模型（S42、298k 等）观测维度是 `[1012, 34]`，三麻是 `[775, 34]`，差 237 个通道，权重结构上不可跨用。

所以三麻只有两条路：自训（需要 4 万局以上语料 + GPU）或者写规则引擎。Calc3P 走第二条，并把规则引擎做到「能算的都算准」：

| 能力 | 做法 | 精度 |
|---|---|---|
| 向听数 | `mahjong` 库 + 三麻规则（`is_three_player=True`） | 精确 |
| 进张数 | 逐种牌剔除可见牌 | 精确 |
| 和牌率 | 枚举和牌张 × 精确二项式 CDF（听牌）／经验表 × 巡目修正（未听） | 听牌精确，未听 ±30% |
| 打点 | 真实番符 → `mahjong` 库标准点数表 | 精确（含本场/供托/拔北/赤宝牌） |
| 铳率 | 现物 / 筋 / 壁 / 立直者危险度 / 字牌分档 | 启发式，量级正确 |

**算不了的**：对手手牌分布、押し引き的价值判断、对手是否在骗听。这些是神经网络的领域，Calc3P 用固定惩罚系数近似，不做概率建模。

## 性能与对拍数据

### 速度

| 指标 | 数值 |
|---|---|
| p50 | 5.6 ms |
| p90 | 12.2 ms |
| p99 | 14.3 ms |
| 最大（120 副随机手牌） | 53.0 ms |
| bot 冷启动 | 86 ms |

对比 `mortal3p` 冷启动 1.5 s、单步 25 ms。

### 决策一致率（3257 个实战决策点）

用作者自己 47 局三麻牌谱回测，逐点对比三家 AI 的首选打牌：

| 对比 | 一致率 |
|---|---|
| Calc3P ↔ mortal3p | **66.0%** |
| Calc3P ↔ 人类 | 51.2% |
| mortal3p ↔ 人类 | 61.6% |

解读要小心：一致率衡量的是「像不像」，不是「强不强」。人类立直判断与 `mortal3p` 只有 25% 一致——人对立直很随意，所以「像人类」不是目标。Calc3P 的目标是对齐 `mortal3p`。

按动作类型拆开：

| 动作 | 决策点 | Calc3P ↔ mortal3p |
|---|---|---|
| 打牌 | 2745 | 62.8% |
| 拔北 | 217 | 96.8% |
| 立直 | 192 | 37.0% |
| 和牌 | 42 | 100% |

立直一致率低是结构性的：`mortal3p` 看得到打点路线期望，Calc3P 只看到「这手牌和了值多少点」。

## 安装

### 前置

- [Akagi](https://github.com/shinkuan/Akagi) 3.8.0 或更新版本
- Python 3.12（Akagi 便携包自带，在 `runtime\python\x86_64-pc-windows-msvc\python.exe`）

### 三步

1. 把整个 `calc3p` 目录复制到 Akagi 的 `mjai_bot\` 下，最终路径形如：

   ```
   akagi-3.8.0-windows-x64\
   └── mjai_bot\
       └── calc3p\
           ├── bot.py
           ├── manifest.toml
           └── pyproject.toml
   ```

2. 打开 Akagi → **Bots** 页 → 找到 `Calc 3P` → 点 **Install environment**

   这会用 `uv` 建一个独立的 venv 并装 `mahjong>=1.4`。若网络受限，也可以手动：

   ```powershell
   $uv = "akagi-3.8.0-windows-x64\runtime\uv\x86_64-pc-windows-msvc\uv.exe"
   & $uv sync --project "akagi-3.8.0-windows-x64\mjai_bot\calc3p"
   ```

3. 打开 `configs\config.toml`（**先退出 Akagi**，运行中改会被覆盖），把三麻 bot 指过来：

   ```toml
   [bot]
   active_4p = "mortal"      # 四麻保持你原来的
   active_3p = "calc3p"      # 三麻用 Calc3P
   dir = "mjai_bot"
   ```

   重开 Akagi，开一局三麻即可。

### 验证

`logs\<session>\bot.log` 里出现类似下面的行，说明在跑：

```
bot reacted action=Dahai { pai: "1m", tsumogiri: false } reaction_ms=7
```

如果看到 `bot spawn failed` 或 `reaction timeout`，检查 `.akagi\venv` 是否存在、`python -c "import mahjong"` 是否成功。

## 界面说明

Akagi 的 Overlay 面板（`[overlay] top_n = 4`）显示四行：

```
┌─────────────────────────────────────┐
│ 何切1  [牌图]  和 24.9% 铳 4.9% 进 33   46% │
│ 何切2  [牌图]  和 28.0% 铳 4.9% 进 37   32% │
│ 何切3  [牌图]  和 17.0% 铳 2.5% 进 11   22% │
│ 期待                          2600        │
└─────────────────────────────────────┘
```

- **何切1/2/3**：推荐打出的三张牌，按「向听优先、同向听比 EV」排序
- **和**：打这张后，未来和牌的概率
- **铳**：这张牌被荣和的概率
- **进**：有效进张的剩余枚数
- **右侧百分比**：选择权重，`softmax(EV / 340)`，降档候选额外扣 600 分/档
- **期待**：首选动作的期望值

拔北时会单独弹出「拔北 / 宝牌 +1」提示；不碰、不杠时会显示理由（无役 / 未推进）。

## 决策模型

### 总流程（自己摸牌时）

```
1. 自摸和牌？
2. 拔北？（退一档向听换宝牌，仅在宝牌 ≥2 张时允许）
3. 暗杠？（不降向听才杠）
4. 立直？（听牌 ≥2 张、有役、打点够、非追立劣势）
5. 打牌（EV 排序取前三）
```

别人打牌时：`荣和 → 大明杠 → 碰 → 不碰（附理由）`。

### EV 计算

```
EV(打 x) = P_win(x) × 打点 − P_deal_in(x) × 4200 − 0.6 × 浮牌价值(x)
```

**浮牌价值**（打掉这张放弃的未来价值）：

| 张数 | 档位 |
|---|---|
| 宝牌 | +600 |
| 赤 5 | +800 |
| 刻子（役牌 / 非役） | 900 / 600 |
| 对子（1 对 / 2 对 / ≥3 对） | 900 / 600 / 450 |
| 两面 / 嵌张 / 边张 | 700 / 450 / 350 |
| 字牌（三元 / 连风 / 自风 / 场风 / 客风） | 340 / 400 / 330 / 200 / 70 |
| 孤张（3-7 / 2、8 / 1p9p / 1m9m） | 400 / 320 / 260 / 150 |

另加邻接加分 `+60 × 相邻牌数`；已参与顺子的浮张 `+350`。

**打点**（未听牌时）：`_expected_han()` 估番数（门清基线 2.5 番、副露 1.5 番，清一色 +5、混一色 +1.2、断幺 +1、七对子 +0.6/对、一气 +1/段），加上宝牌数，按标准番符表折算（符数统一取 30）。

**铳率**：

| 情况 | 概率 |
|---|---|
| 现物 | 0 |
| 立直者宣言牌之后的安全牌 | 0 |
| 筋 | 4% |
| 壁（4 张全见） | 3% |
| 字牌（三元 / 下家自风 / 他家中风 / 场风 / 客风 / 北） | 4.5% / 4.2% / 3.2% / 3.5% / 2% / 2% |
| 数牌无信息 | 2.5% |
| 立直者场上 + 危险度加成 | 最高 38% |

## 三麻规则适配

三麻和四麻的差异全部显式处理，这是 Calc3P 最多 bug 的地方，也是最有价值的地方：

| 规则 | 处理 |
|---|---|
| **没有 2m–8m** | 牌种只剩 27 种 / 108 张。`_is_dead_tile` 硬排除这 7 种；`1m`/`9m` 永远组不成顺子，浮牌价值按客风档（150）算 |
| **不能吃** | 只有碰、明杠、暗杠、加杠 |
| **无食い断幺** | 副露后断幺不算役，`_has_viable_yaku` 对副露强制要求其他役 |
| **拔北** | 北可拔（+1 宝牌），拔完补一张。拔北判断：拔后向听不降才拔，宝牌 ≥2 张时允许退一档 |
| **北不是役牌** | 北刻子没有 Yakuhai，只有拔北宝牌 |
| **自摸损** | 庄家 1.5 倍、闲家自摸 2/3 分摊，全部交给 `mahjong` 库算 |
| **本场 / 供托** | `HandConfig(tsumi_number=honba, kyoutaku_number=kyotaku)` |
| **自风随场风旋转** | 庄家自风 = 场风；`seat_wind_of()` 按 `order[(base + 相对座次) % 3]` 计算 |
| **赤宝牌位置** | 赤 5 固定占该牌种 slot 0（5m=16、5p=52、5s=88），非赤从 slot 1 起分配 |
| **宝牌循环** | `1m↔9m` 循环，与四麻不同，需要合成指示牌喂给库 |

## 已知限制

诚实列出，不打算修或优先级低：

1. **立直判断弱**。与 `mortal3p` 只有 37% 一致。根因是没有「打点路线期望」建模——`mortal3p` 会算「这手牌走立直直击 / 自摸 / 流局的加权收益」，Calc3P 只看当前和了值。
2. **不防役满**。对手做国士、四暗刻时铳率仍按 4200 点损失估。作者判断这是黑天鹅（500 局撞 1 次），专项识别准确率做不到 95% 以上就是净亏。
3. **对手听牌概率是启发式**。不做贝叶斯推断，只看舍牌序列 + 筋 + 壁。
4. **押し引き是固定系数**。`4200` 点放铳惩罚不随巡目、点数状况、庄闲变化。
5. **副露判断保守**。无役必不碰，宁可错过提速机会。
6. **暗杠判断缺失**（对拍 7 个点全错）。目前只在「不降向听」时杠，没考虑杠后宝牌收益与手牌结构变化。

## 遥测（默认开启，但只发本机，每周一次）

默认行为：**每局在本地记一条统计，地址是本机回环 `127.0.0.1:8801`，每 7 天最多发送一次**。不填公网地址，数据出不了你自己的电脑——作者收不到任何东西。

想真正上报，在 `bot.py` 同目录建 `telemetry.toml`：

```toml
[telemetry]
enabled = true
endpoint = "https://你自己部署的接收端/collect"   # 换成你的服务器
include_hands = false                            # true 时附带每手 14 张手牌
```

完全关闭：

```toml
[telemetry]
enabled = false
```

上报字段（不含账号、机器指纹、对手信息）：

| 字段 | 内容 |
|---|---|
| `install_id` | 首次运行随机生成的 32 位十六进制串，可随时删除重置 |
| `bot_version` / `python` / `os` | 版本信息 |
| `reason` | 结束原因（`end_game` / `eof`） |
| `game.decisions` / `errors` / `actions` | 本局决策数、异常数、动作分布 |
| `game.p50_ms` / `p99_ms` | 决策耗时分位数 |
| `hands` | 仅 `include_hands = true` 时，最多 200 条手牌 + 动作 |

本地队列在 `~/.calc3p/queue.jsonl`，最多 500 条；发送成功后清空并记录 `~/.calc3p/last-flush`；发送失败静默保留，7 天后重试，绝不影响对局。

**作者不运营接收端**，你需要自己部署。仓库里的 `server/collector.py` 是只用标准库的最小实现（按日写 JSONL，见 [`server/README.md`](server/README.md)）。

完整字段与不采集项见 [`PRIVACY.md`](PRIVACY.md)。

## 开发与测试

`bot.py` 单文件 1494 行，无内部模块拆分（Akagi 的 bot 契约要求单入口 `bot.py`）。

主要函数：

| 函数 | 作用 |
|---|---|
| `State.consume(event)` | 事件驱动的状态机（手牌/舍牌/副露/立直/宝牌/拔北） |
| `_shanten(hand34)` | 向听数，三麻规则 |
| `_winning_tiles` / `_improving_tiles` | 和牌张 / 有效进张 |
| `_estimate_value` | 听牌后的和了点数（精确） |
| `_expected_han` + `_standard_points` | 未听牌的打点估算 |
| `_win_probability` | 和牌率 |
| `_danger` / `_is_safe` | 铳率 |
| `_float_value` | 浮牌价值 |
| `_score_discard` | 单张打牌的完整评分 |
| `_rank_scores` | 向听优先排序 |
| `decide_after_own_tsumo` / `_others_dahai` / `_own_pon` / `_own_reach_echo` | 各分支决策 |

测试：

```bash
python test_calc3p.py      # 7 个场景、59 行输出，全部通过才算过
```

调试：`bot.py` 在 stderr 打印每步决策链（`# dahai pick=... top=[...] hand=...`），格式见 `logs\<session>\bot.log`。
