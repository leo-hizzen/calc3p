# 决策模型设计

Calc3P 的核心是一个单一的期望值函数，所有决策都是它的变体：

```
EV(动作) = P(和牌) × 打点 − P(放铳) × 放铳损失 − 放弃的未来价值
```

理解这个式子的分量权重，就理解了 Calc3P 的行为。

---

## 1. 为什么是 EV 而不是「优先级清单」

规则引擎有两种写法：

**写法 A（优先级清单）**
```
能自摸就自摸 → 能杠就杠 → 听牌就立直 → 否则按向听打
```

**写法 B（统一 EV）**
```
枚举所有合法动作，每个算一个分，取最高
```

Calc3P 用 B。原因是三麻的决策经常互相冲突——「听牌但打点极低」和「一向听但清一色」哪个好？清单没法回答，EV 能。

但纯 EV 有两个坑，都踩过：

### 坑 1：向听倒退被合理化

早期版本里，3 向听打 7p（进张 45 张）的 EV 是 −138.6，2 向听打南（进张 10 张）是 −151.1，于是 bot 选了 3 向听。

进张多 35 张这个优势，足以抵消退一个向听的劣势——单看 EV 确实如此。但那手牌有 9s、9s、西、西、白、發一堆孤张字牌，退向听是自毁。

**修法**：先按向听分档，同档内比 EV。

```python
def _rank_scores(scores):
    viable = [s for s in scores if s.live > 0] or scores
    best_sh = min(s.shanten for s in viable)
    return sorted(viable, key=lambda s: (s.shanten != best_sh, -s.ev))
```

活牌为 0 的候选（已经没得摸了）才允许降档。

### 坑 2：降档候选软权重

`softmax(EV / 340)` 直接作用于三张候选，导致「排第三的牌挂 57% 权重」——因为它的 EV 只比第一名低一点，但向听差了一档。

**修法**：softmax 前按降档扣分。

```python
adj = [c.ev - (c.shanten - best_sh) * 600.0 for c in cands]
```

## 2. 和牌率 P(win)

### 听牌时：精确枚举

```
P(和牌) = Σ_{和牌张 t} P(在剩余 N 巡内摸到 t)
```

对每种和牌张，剩余枚数 `live_t` 已知（108 张减去已见牌），`N` 是剩余巡数。用二项式的补事件形式：

```
P(至少摸到一张) = 1 − C(总剩 − live_t, N) / C(总剩, N)
```

再乘一个 0.82 的折损系数——因为对手会先和、会鸣牌打断、会和牌张被别家用掉。

### 未听牌时：经验表

没有精确模型（要精确就得给整手牌算 DP，代价高且收益低），用经验表：

| 向听 | 基准和牌率 |
|---|---|
| 1 | 0.42 |
| 2 | 0.28 |
| 3 | 0.17 |
| 4 | 0.10 |
| 5 | 0.06 |

再按两个因子修正：

```
P = base × clamp(live / ref, 0.50, 1.30) × (remaining_turns / 18)
```

`live` 是有效进张的剩余枚数，`ref` 是该向听的参考进张数。系数跨度从最初的 4.3 倍收紧到 2.6 倍——早期版本给 1 向听 100% 和牌率，明显失真。

> 实测校准：2 向听的真实和牌率约 25%，模型给 12.8%（改前）→ 现在约 20%。仍偏保守，这是有意的：宁可低估和率，也不要高估后去冒险。

## 3. 打点

### 听牌时：精确

调用 `mahjong` 库算真实番符：

```python
_hand_value(state, hand34_14, aka, win_idx, is_tsumo, nuki, riichi)
# → HandResponse(han=5, fu=30, yaku=[...], cost={'total': 8000, ...})
```

对每个和牌张取 `max(自摸, 荣和)`，按剩余枚数加权平均。

### 未听牌时：估番 + 标准表

未听牌没有和牌形，符数算不出，但番数可以估：

```python
def _expected_han(state, hand13) -> float:
    han = 2.5 if state.is_closed() else 1.5      # 基线
    han += 5.0 * min(1, (main_suit - 9) / 4)     # 清一色倾向
    han += 1.2 * min(1, (main_suit - 8) / 4)     # 混一色倾向
    han += 1.0 if yaochuu == 0 else 0.3          # 断幺倾向
    han += 0.6 * (pairs - 3)                     # 七对子倾向
    han += 1.0 * (blocks - 1)                    # 一气倾向
    return han
```

基线 2.5 的来由：门清手牌的平均和牌方式约等于「立直 1 番 + 门清自摸 1 番 + 宝牌 0.5 番」。副露已经花掉一个役，降到 1.5。

然后按标准番符表折点数（符数统一 30）：

```python
def _standard_points(han, fu, dealer) -> float:
    if han >= 13: base = 8000
    elif han >= 11: base = 6000
    elif han >= 8: base = 4000
    elif han >= 6: base = 3000
    elif han >= 5: base = 2000
    elif han == 4 and fu >= 40: base = 2000
    elif han == 3 and fu >= 70: base = 2000
    else: base = fu * 2 ** (2 + han)
    return base * (6 if dealer else 4)
```

**这一条是用户提出的**：「打点不是有标准计算公式吗？直接计算番数和符数就好了呀」。改之前是固定常数 2600/1800，宝牌、赤五、拔北全没进——手里两张宝牌的 2 向听和零宝牌估值一样。

## 4. 铳率 P(放铳)

完全启发式，优先级从高到低：

| 判断 | 概率 | 依据 |
|---|---|---|
| 现物（立直者打过） | 0% | 绝对安全 |
| 立直宣言牌之后打过的牌 | 0% | 同上 |
| 壁（该牌 4 张全见） | 3% | 两边都碰不到 |
| 筋（立直者两面听不到） | 4% | 概率性安全 |
| 字牌：三元 | 4.5% | 有役、容易留 |
| 字牌：下家自风 | 4.2% | 下家鸣牌吃掉我的摸牌 |
| 字牌：其他家自风 | 3.2% | |
| 字牌：场风 | 3.5% | 三家都能用 |
| 字牌：客风 / 北 | 2% | 最废 |
| 数牌无信息 | 2.5% | 基准 |

立直者场上再加危险度加成，最高到 38%。

### 放铳损失 = 2291

固定常数，不随巡目、点数、庄闲变化。这个数字是 64 局、4,564 个自由弃牌点上拟合出来的：初版取 4200（按「三麻平均和了 5200 点 × 80% 确实放铳」推），结果把 1% 的铳率定价成 42 点，导致 Bot 过度弃和。降到 2291 后，`calc↔mortal` 一致率单独贡献约 6.6pp。

**这仍是已知的过度简化**。押し引き（该攻该守）本该由「当前点差、剩余巡目、和牌收益、放铳损失」联合决定，Calc3P 只用一个常数代替。

## 5. 浮牌价值

「打掉这张牌，未来会少多少机会」。这是调得最久的一块，v1.2.2 的 27 个系数里有 19 个在这一块。

评分逻辑（按优先级）：

```
1. 宝牌        +600
2. 赤 5       +800
3. 刻子       役牌 667 / 非役 615
4. 对子       1 对 482 / 2 对 477 / 3 对以上 474
   └─ 若其中一张要配顺子 → 反转为 +350（伪对子）
5. 搭子       两面 625 / 嵌张 442 / 边张 439
6. 字牌       三元 158 / 连风 304 / 自风 172 / 场风 167 / 客风 95
7. 孤张       3-7 中张 300 / 2、8 227 / 1p9p 163 / 1m9m 60
8. 邻接加分   +69.6 × 同花色相邻牌数
```

对子三档几乎塌缩成一条平线（482/477/474），这是个有意义的结论：**三麻里对子的价值与数量基本无关**，几对都只是「差一个刻子」的同一回事。同理，1m/9m 的 60 与孤张字牌的 95 很接近——三麻没有 2m–8m，1m/9m 永远组不成顺子，只能靠暗刻或作雀头。

### 调参历史

| 版本 | 字牌档 | 结果 |
|---|---|---|
| 初版 | 三元 900 / 连风 700 / 自风 600 / 场风 400 / 客风 150 | 过度珍惜字牌，`calc↔mortal` 57.7% |
| 第一轮 | 420 / 480 / 400 / 260 / 100 | 62.0% |
| 第二轮 | 340 / 400 / 330 / 200 / 70 | 62.3% |
| **v1.2.2 拟合** | **158 / 304 / 172 / 167 / 95** | **71.0%** |

前两轮是手工二分试调，各涨不到 1 点；v1.2.2 换成 64 局 4,564 个自由弃牌点的批量拟合后，字牌维度和其它维度一起被推到 71.0%。

### 整体缩放 1.0813

早期版本担心浮牌价值跨度过大（150 到 900）会压过「升一个向听」的收益（约 420），于是乘了 0.6。但拟合结果显示这是错的：最优缩放是 **1.0813**，也就是浮牌价值应当比现在「更重要」而不是更轻。原因是 v1.2.2 已经把各档的绝对值大幅下调（最高 667 而非 900），跨度收窄到 667–60，再乘 0.6 就过度轻视了。

```python
ev -= 1.0813 * _float_value(state, idx, hand14)
```

## 6. 立直判断

```python
ok = 听牌张数 >= 2                                    # 至少两面或双碰
if value_plain > 0 and not (张数 >= 4 or 打点 >= 5200):
    ok = False                                        # 有明役就不必立直
if 有人立直 and not (张数 >= 4 or 打点 >= 8000):
    ok = False                                        # 追立需要好形或高打点
```

**这是弱项**。与 `mortal3p` 只有 37% 一致，因为 `mortal3p` 算的是「立直后直击 / 自摸 / 流局的加权期望」，Calc3P 只看当前和了值。

但要注意：**不能用人类当基准**。`mortal3p` 与人类的立直判断只有 25% 一致——人对立直的取舍非常随意（有时为了听牌率不立、有时无脑立）。Calc3P 的目标是对齐前者。

## 7. 鸣牌判断

```python
# 碰
if 有役 and 碰后向听 < 当前向听:
    碰
else:
    不碰（附理由：无役 / 未推进）
```

无役必不碰是硬规则。三麻没有食い断幺，副露后无役等于自杀。

**代价**：错过了不少提速机会——有时碰了虽然无役，但可以转成混一色、一气通贯。当前版本不做这个推演。

## 8. 并行与性能

单步决策把所有候选都算一遍：

```
13 张候选 × (向听计算 + 进张枚举 + 和牌率 + 打点 + 铳率)
```

实测 p50 5.6 ms。不需要任何优化——Akagi 给的预算 3000 ms。

唯一的性能隐患是 `_shanten` 调用次数：`_score_discard` 里每张候选算一次向听，`_improving_tiles` 里再对每种进张算一次。如果将来要支持四麻或更复杂的评估，需要缓存。
